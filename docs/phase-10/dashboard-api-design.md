# Phase 10 Dashboard API Design

## Purpose

The dashboard API exposes exported evaluation data as clean JSON for the frontend. It is intentionally read-only in Phase 10.

## Data File

Primary source:

```text
data/evaluation/dashboard-summary.json
```

Generated by:

```powershell
python scripts/export_dashboard_data.py
```

## Endpoints

### `GET /evaluation/summary`

Returns headline metrics, generated timestamp, run count, failed-question count, and notes.

### `GET /evaluation/runs`

Returns compact metadata and metrics for every exported run.

### `GET /evaluation/runs/{run_id}`

Returns one complete run object.

### `GET /evaluation/compare`

Returns overview metrics, comparison summaries, and all runs.

### `GET /evaluation/failed-questions`

Returns failed-question records from exported failed-question reports.

## Error Behavior

If `data/evaluation/dashboard-summary.json` does not exist, the API returns a 404 with a clear instruction to run:

```powershell
python scripts/export_dashboard_data.py
```

## Phase 10 Boundary

The API does not start new evaluations, mutate benchmark data, or persist dashboard records to PostgreSQL. Database-backed evaluation history can be added later if the project needs it.
